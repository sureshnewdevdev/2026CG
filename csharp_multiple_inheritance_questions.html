5 Medium-Level C# Questions: Multiple Inheritance Concepts

Note: While C# does not support multiple class inheritance to avoid the architectural "Diamond Problem," it relies on interfaces and composition to achieve the same behaviors. These questions test your ability to work around this limitation.

1. Resolving Method Name Collisions (Explicit Implementation)

You have two interfaces, IPrinter and IScanner. Both interfaces declare a void method named Initialize(). Create a MultiFunctionDevice class that implements both interfaces. Write the code so that calling Initialize() behaves differently depending on whether the object is cast as an IPrinter or an IScanner.

Challenge: Ensure that the Initialize() method cannot be called directly on an instance of MultiFunctionDevice without casting.

2. The C# 8.0 Diamond Problem (Default Interface Methods)

Create an interface IDevice with a default method implementation void PowerOn() => Console.WriteLine("Device On");. Create two more interfaces, ILaptop and ITablet, which both inherit from IDevice and override the PowerOn() default method with their own console outputs. Finally, write a HybridComputer class that implements both ILaptop and ITablet.

Challenge: Write the necessary code inside HybridComputer to resolve the compiler error caused by inheriting two different default implementations of PowerOn().

3. Mixing Base Classes and Multiple Interfaces

Design a system for a smart home. You have an abstract base class Appliance with an abstract method TurnOff(). You also have two interfaces: IWiFiConnected (requires a ConnectToNetwork(string ssid) method) and IEnergyEfficient (requires a double CalculatePowerSaving() method).

Challenge: Write a SmartThermostat class that inherits from Appliance and implements both interfaces. Demonstrate how you would instantiate this class and call methods from the base class and both interfaces.

4. Simulating Multiple Class Inheritance via Composition

You are building a game engine where a PlayerCharacter needs the behaviors of two distinct existing classes: CombatSystem (methods: Attack(), Defend()) and InventorySystem (methods: AddItem(), DropItem()). Since PlayerCharacter cannot inherit from both classes, refactor this design.

Challenge: Extract interfaces ICombatant and IInventory from the respective classes. Write the PlayerCharacter class so it implements both interfaces by using composition (holding instances of CombatSystem and InventorySystem internally) to delegate the actual logic, thereby faking multiple inheritance.

5. Deep Interface Inheritance Chains

Define two foundational interfaces: IReadable (contains string Read()) and IWritable (contains void Write(string data)). Create a third interface, IFileStream, that inherits from both IReadable and IWritable, and adds a new method void Close().

Challenge: Write a SecureDocument class that implements IFileStream. Add a twist: make the Write() method throw an UnauthorizedAccessException unless a boolean property IsUnlocked is true.
