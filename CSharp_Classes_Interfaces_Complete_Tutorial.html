Topic 01 / 13

Sealed classes

What is it?

A sealed class is a class that other classes cannot inherit from. Think of a final certificate format: you can create and use certificates, but you deliberately close the option of extending the class through inheritance.

Why and when would we use it?

Use sealed when a type is intentionally complete and subclasses could break its assumptions. In our training application, a certificate formatter has a fixed responsibility. Sealing is a design decision; it does not make an object immutable or secure its data.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public sealed class CertificateService
{
    public string Create(string learner) => $"Certificate issued to {learner}";
}

public class Program
{
    public static void Main()
    {
        var service = new CertificateService();
        Console.WriteLine(service.Create("Anu"));
        // Uncomment to see the separate invalid declaration below:
        // public class CustomService : CertificateService { }
    }
}
// Invalid at namespace scope too:
// public class CustomService : CertificateService { }

Expected output

Certificate issued to Anu

How the code works

  1. sealed appears before class and stops subclassing.
  2. Create is an ordinary instance method: an object is still required.
  3. The commented subclass must be declared outside Main to demonstrate the inheritance error.

Benefit

Makes the intended inheritance boundary explicit and prevents unsupported overrides through subclasses.

Limitation and how to handle it

A subclass cannot customize the behavior. Use composition, an interface, or a deliberately extensible class when variation is needed.

Common mistake: Do not confuse sealed with static. A sealed class can have instances. Do not combine abstract and sealed on an ordinary class.

Topic 02 / 13

Creating interfaces

What is it?

An interface describes a capability that a type agrees to provide. For example, INotifier promises a Send method without forcing the caller to know how the message is delivered.

Why and when would we use it?

A training system might send enrollment messages by email or SMS. The enrollment code can depend on INotifier so delivery implementations can be replaced.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public interface INotifier
{
    void Send(string message);
}

public class EmailNotifier : INotifier
{
    public void Send(string message) => Console.WriteLine($"Email: {message}");
}

public class Program
{
    public static void Main()
    {
        INotifier notifier = new EmailNotifier();
        notifier.Send("Welcome to C# training");
    }
}

Expected output

Email: Welcome to C# training

How the code works

  1. interface declares a type whose members describe the contract.
  2. The colon in EmailNotifier : INotifier declares implementation.
  3. public void Send matches the required signature for implicit implementation.
  4. The interface variable holds a reference to an EmailNotifier object; no interface object is created.

Benefit

Separates callers from implementations, supporting testing and replacement.

Limitation and how to handle it

Too many tiny interfaces can complicate simple code. Use them for meaningful boundaries. Modern interfaces can have default implementations; this lesson starts with bodyless required members.

Common mistake: new INotifier() is invalid. A missing required member or a non-public implicit implementation produces a compiler error.

Live trainer demonstration

Topic 03 / 13

Implementing interface inheritance

What is it?

An interface can inherit another interface and add more requirements. A class that implements the derived interface must satisfy the inherited contract as well as the added members, unless a suitable default implementation supplies a member.

Why and when would we use it?

Every enrolled learner can introduce themselves. An assessable learner must also take an assessment. IAssessableLearner combines those capabilities.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public interface ILearner
{
    void Introduce();
}

public interface IAssessableLearner : ILearner
{
    void TakeAssessment();
}

public class Trainee : IAssessableLearner
{
    public void Introduce() => Console.WriteLine("I am learning C#");
    public void TakeAssessment() => Console.WriteLine("Assessment started");
}

public class Program
{
    public static void Main()
    {
        IAssessableLearner learner = new Trainee();
        learner.Introduce();
        learner.TakeAssessment();
        ILearner basic = learner;
        basic.Introduce();
    }
}

Expected output

I am learning C#
Assessment started
I am learning C#

How the code works

  1. IAssessableLearner : ILearner extends the interface contract.
  2. Trainee implements both required methods.
  3. Assigning the derived interface reference to ILearner is allowed.
  4. basic.TakeAssessment() would not compile because ILearner does not declare it.

Benefit

Builds related capability contracts without forcing a shared class hierarchy. An interface may inherit multiple interfaces.

Limitation and how to handle it

Deep interface hierarchies are harder to understand. Prefer focused capabilities; combine contracts only when the relationship is meaningful.

Common mistake: Implementing only TakeAssessment is insufficient here. Interface inheritance does not create an inherited data field or a base-class constructor.

Live trainer demonstration

Remove Introduce from Trainee and build. Restore it. Then change the variable type to ILearner and explain why TakeAssessment is unavailable.

Topic 04 / 13

Declaring properties within interfaces

What is it?

An interface property specifies what data access a caller can expect. string Name { get; set; } requires readable and writable access. int Id { get; } requires readable access only through that interface.

Why and when would we use it?

Different learner classes can expose a common Id and Name so a report generator can read them through ILearnerProfile.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public interface ILearnerProfile
{
    int Id { get; }
    string Name { get; set; }
}

public class Learner : ILearnerProfile
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
}

public class Program
{
    public static void Main()
    {
        var learner = new Learner { Id = 101, Name = "Anu" };
        ILearnerProfile profile = learner;
        profile.Name = "Anu Kumar";
        Console.WriteLine($"{profile.Id}: {profile.Name}");
        // profile.Id = 102; // No setter on this interface.
    }
}

Expected output

101: Anu Kumar

How the code works

  1. The interface declarations do not allocate instance storage.
  2. The class uses auto-implemented properties, whose storage is generated by the compiler.
  3. profile.Name can be assigned because the interface includes set.
  4. learner.Id can be assigned because the concrete class exposes a public setter.

Benefit

Gives callers a consistent data-access contract while allowing each class to manage storage and validation differently.

Limitation and how to handle it

A get-only interface view does not guarantee that the underlying object is immutable. Use a more restrictive concrete design if mutation must be prevented.

Common mistake: Do not describe a bodyless interface property as an auto-implemented instance property: it is a contract, without an instance backing field.

Live trainer demonstration

Try assigning profile.Id and observe the error. Then assign learner.Id and explain the difference between reference type and object type.

// In Learner:

// In Main:

Namespaces

What is it?

A namespace is a logical naming container for related types. It helps organize names and distinguish classes with the same short name.

Why and when would we use it?

A training application and a billing application may both define a Report class. Their fully qualified names make their meanings unambiguous.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;
using TrainingReport = Training.Reports.Report;
using BillingReport = Billing.Reports.Report;

namespace Training.Reports
{
    public class Report
    {
        public string Title => "Attendance report";
    }
}

namespace Billing.Reports
{
    public class Report
    {
        public string Title => "Fee report";
    }
}

public class Program
{
    public static void Main()
    {
        Console.WriteLine(new TrainingReport().Title);
        Console.WriteLine(new BillingReport().Title);
    }
}

Expected output

Attendance report
Fee report

How the code works

  1. Training.Reports.Report is the fully qualified type name.
  2. using TrainingReport = ... creates an alias for that type.
  3. A using directive affects name lookup; it does not copy source code or install a package.
  4. Block-scoped namespaces allow this single-file demo to declare two namespaces.

Benefit

Reduces naming conflicts and groups related types clearly.

Limitation and how to handle it

Long or inconsistent namespaces are cumbersome. Follow a predictable project naming scheme and use aliases when names collide.

Common mistake: A folder does not automatically enforce a namespace. A missing assembly/package reference cannot be fixed only by adding using.

Live trainer demonstration

Creating and using generic classes

What is it?

A generic class uses a type parameter such as T so one class definition can work with different concrete types while retaining compile-time type checks.

Why and when would we use it?

A training application needs lists of learners and courses. Repository<T> can store either kind of object without making callers cast values from object.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;
using System.Collections.Generic;

public class Repository<T>
{
    private readonly List<T> items = new List<T>();
    public void Add(T item) => items.Add(item);
    public T Get(int index) => items[index];
    public int Count => items.Count;
}

public class Learner
{
    public string Name { get; set; } = "";
}

public class Course
{
    public string Title { get; set; } = "";
}

public class Program
{
    public static void Main()
    {
        var learners = new Repository<Learner>();
        learners.Add(new Learner { Name = "Anu" });
        var courses = new Repository<Course>();
        courses.Add(new Course { Title = "C#" });
        Console.WriteLine(learners.Get(0).Name);
        Console.WriteLine(courses.Get(0).Title);
        // learners.Add(new Course()); // Wrong type.
    }
}

Expected output

Anu
C#

How the code works

  1. T is a placeholder for a type, not a value or a particular built-in type.
  2. List<T> is itself a generic collection.
  3. Repository<Learner>.Add accepts Learner objects.
  4. Get returns T, so the caller receives the correct type without an explicit cast.

Benefit

Reuses code with type safety. Generic collections of value types can avoid the boxing involved in object-based storage.

Limitation and how to handle it

An unconstrained T does not promise members such as Name. Add a meaningful interface constraint when generic logic requires specific capabilities. This example is in-memory storage, not a database repository.

Common mistake: Get(99) on a short list fails at runtime. Generics validate types, not index bounds. Do not use object everywhere when type safety is needed.

Live trainer demonstration

Indexers and properties

What is it?

A property exposes a named value such as batch.Count. An indexer exposes a value selected by an argument, such as batch[0]. Indexers make collection-like objects natural to use.

Why and when would we use it?

A Batch object contains learner names. Count describes the whole batch, while batch[index] reads or updates one learner.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public class Batch
{
    private readonly string[] names = { "Anu", "Ravi", "Meena" };
    public int Count => names.Length;

    public string this[int index]
    {
        get => names[index];
        set => names[index] = value;
    }
}

public class Program
{
    public static void Main()
    {
        var batch = new Batch();
        Console.WriteLine(batch.Count);
        Console.WriteLine(batch[1]);
        batch[1] = "Ravi Kumar";
        Console.WriteLine(batch[1]);
    }
}

Expected output

3
Ravi
Ravi Kumar

How the code works

  1. this[int index] declares an indexer that accepts an integer.
  2. The names array is zero-based, so index 1 selects Ravi.
  3. value inside set is the incoming string.
  4. readonly prevents replacing the array reference here; it does not prevent changing its elements.

Benefit

Provides concise, readable access to collection-like objects while keeping storage private.

Limitation and how to handle it

Unexpected indexing rules confuse callers. Document valid keys or bounds. Indexers can use string or other parameter types and can be overloaded with distinct parameter lists.

Common mistake: batch[3] is out of range because the valid indexes are 0, 1 and 2. An ordinary named property cannot accept parameters in C#.

Live trainer demonstration

Read each index aloud, change one element, then deliberately try index 3. Explain how a real API should choose and document its invalid-index behavior.

Auto-implemented properties

What is it?

An auto-implemented property uses accessor declarations such as get; set; without custom accessor bodies. The compiler supplies the private backing field.

Why and when would we use it?

Learner data such as Name and Course often needs simple storage. Auto-properties keep these declarations short. A private setter lets the class control updates to a value such as CompletedTasks.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public class Learner
{
    public string Name { get; set; } = "Unknown";
    public string Course { get; set; } = "C#";
    public int CompletedTasks { get; private set; }
    public void CompleteTask() => CompletedTasks++;
}

public class Program
{
    public static void Main()
    {
        var learner = new Learner { Name = "Anu" };
        learner.CompleteTask();
        Console.WriteLine($"{learner.Name} | {learner.Course}");
        Console.WriteLine(learner.CompletedTasks);
    }
}

Expected output

Anu | C#
1

How the code works

  1. Name and Course are auto-properties with initial values.
  2. The compiler creates storage; you do not declare a separate field.
  3. CompletedTasks starts at the default int value, zero.
  4. private set permits assignment within Learner, including CompleteTask.

Benefit

Reduces repetitive code and keeps simple data models readable.

Limitation and how to handle it

Plain get; set; does not validate input. Use an explicit backing field and accessor bodies when validation is needed; do not assume an initializer is a validation rule.

Common mistake: learner.CompletedTasks = 100 cannot compile outside Learner. Auto-properties are not public fields, even when their usage syntax looks similar.

Topic 09 / 13

Static classes

What is it?

A static class groups members that are accessed through the class name. You cannot create an instance of a static class. It cannot be used as a base class.

Why and when would we use it?

A small fee calculation that depends only on its inputs can be a static utility. It does not need a different object for each learner.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public static class FeeCalculator
{
    public static decimal Calculate(decimal fee, decimal discountPercent)
    {
        if (fee < 0 || discountPercent < 0 || discountPercent > 100)
            throw new ArgumentOutOfRangeException(nameof(discountPercent),
                "Fee must be nonnegative and discount must be 0 to 100.");
        return fee - fee * discountPercent / 100m;
    }
}

public class Program
{
    public static void Main()
    {
        decimal result = FeeCalculator.Calculate(10000m, 10m);
        Console.WriteLine(result.ToString("0.00",
            System.Globalization.CultureInfo.InvariantCulture));
    }
}

Expected output

9000.00

How the code works

  1. Both the class and Calculate method are static.
  2. The m suffix creates a decimal literal.
  3. The formula subtracts 10 percent of 10000.
  4. InvariantCulture makes the demonstrated decimal output consistent across machines.

Benefit

Convenient for stateless utility operations and shared constants.

Limitation and how to handle it

Mutable static state is shared within its loaded type context and can cause test interference or concurrency problems. Prefer instance services when behavior needs dependencies or per-object state.

Common mistake: new FeeCalculator() and instance members inside a static class are invalid. A static class is not the same concept as a singleton object.

Live trainer demonstration

Calculate fees for two inputs, then attempt to instantiate FeeCalculator. Explain why a pure function is easy to reason about.

Topic 10 / 13

Property accessors

What is it?

Accessors are the get, set and init parts of a property. get returns a value. set handles a normal assignment. init allows assignment during object initialization, with additional language rules for construction-time contexts.

Why and when would we use it?

A training score must stay between 0 and 100. A property setter can reject invalid values so the object does not accept an invalid score.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public class Assessment
{
    private int score;
    public string AttemptId { get; init; } = "";

    public int Score
    {
        get { return score; }
        set
        {
            if (value < 0 || value > 100)
                throw new ArgumentOutOfRangeException(nameof(value),
                    "Score must be between 0 and 100.");
            score = value;
        }
    }
}

public class Program
{
    public static void Main()
    {
        var test = new Assessment { AttemptId = "A1", Score = 85 };
        Console.WriteLine($"{test.AttemptId}: {test.Score}");
        try { test.Score = 120; }
        catch (ArgumentOutOfRangeException)
        { Console.WriteLine("Rejected invalid score"); }
        Console.WriteLine(test.Score);
    }
}

Expected output

A1: 85
Rejected invalid score
85

How the code works

  1. score is the private storage field; Score is the public property.
  2. value is the special parameter supplied to set.
  3. AttemptId uses init, so test.AttemptId = "A2" after construction would fail to compile.
  4. Validation runs before assignment, so rejection preserves 85.

Benefit

Centralizes simple validation and controls who can change data.

Limitation and how to handle it

Properties should not surprise callers with expensive work or hidden network operations. For complex workflows, use a clearly named method. init is not deep immutability for referenced mutable objects.

Common mistake: Writing Score = value inside its own setter causes recursion. Assign the backing field score instead. Do not use exception handling as a replacement for a clear input UI.

Live trainer demonstration

Run valid, boundary and invalid values: 0, 100, -1, 101. Ask students which values should be accepted before running.

Partial types

What is it?

The partial keyword lets one type be declared in multiple source-code parts. The compiler combines those parts into one type; it does not create a parent and child relationship.

Why and when would we use it?

A generated learner model can live in one file while custom reporting behavior lives in another. Keeping generated and handwritten code separate reduces the chance that regeneration overwrites custom work.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

// Learner.Data.cs (may be a separate file)
public partial class Learner
{
    public string Name { get; set; } = "";
}

// Learner.Actions.cs (may be a separate file)
public partial class Learner
{
    public void Introduce() => Console.WriteLine($"Hello, I am {Name}");
}

// Program.cs
public class Program
{
    public static void Main()
    {
        var learner = new Learner { Name = "Anu" };
        learner.Introduce();
    }
}

Expected output

Hello, I am Anu

How the code works

  1. Both declarations use public partial class Learner.
  2. The complete demo can run from one file, but splitting the marked parts into separate files demonstrates the usual purpose.
  3. All parts must form the same type in the same namespace and assembly/module compilation.
  4. Partial class members can access each other, including private members.

Benefit

Supports generated-code separation and manageable source files. Partial declarations also apply to supported structs, interfaces and record types.

Limitation and how to handle it

Splitting a very large class does not fix excessive responsibilities. Use separate collaborating classes when the design needs separate responsibilities.

Common mistake: A spelling or namespace mismatch creates a different type. Conflicting declarations or duplicate members cause errors. Do not remove partial from one part.

Extension methods

What is it?

An extension method is a static method that can be called using instance-method syntax on its receiver type. It lets you add convenient operations without editing or inheriting the original type.

Why and when would we use it?

A training report repeatedly formats learner names. A string extension can express the operation as name.ToLearnerLabel(). This is a small formatting helper, not a change to the built-in string type.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public static class LearnerTextExtensions
{
    public static string ToLearnerLabel(this string name)
    {
        if (string.IsNullOrWhiteSpace(name))
            return "Learner: Unknown";
        return $"Learner: {name.Trim()}";
    }
}

public class Program
{
    public static void Main()
    {
        string name = "  Anu  ";
        Console.WriteLine(name.ToLearnerLabel());
        Console.WriteLine(LearnerTextExtensions.ToLearnerLabel(name));
    }
}

Expected output

Learner: Anu
Learner: Anu

How the code works

  1. The containing class is top-level, non-generic and static.
  2. The method is static, and this marks its first parameter as the receiver.
  3. Trim removes leading and trailing whitespace and returns a string.
  4. Both calls invoke the same method. A suitable real instance method takes precedence over an extension method.

Benefit

Improves readability for focused operations on existing types, including types you do not own.

Limitation and how to handle it

An extension does not gain access to private members and does not override virtual behavior. Too many broad extensions can make APIs harder to discover. Put them in clear namespaces.

Common mistake: Without this, the method is an ordinary static helper and the instance-style call is unavailable. If extensions are in another namespace, import it with using.

Object initializers

What is it?

An object initializer assigns accessible instance properties or fields as part of a new expression. It makes initial object values easy to read without requiring a constructor overload for every combination.

Why and when would we use it?

When enrolling a learner, set Id, Name and Course together so the code clearly shows the initial values.

Build and run the example

  1. Open this topic’s project folder, or create a new C# Console App.
  2. Replace Program.cs with the complete code below. Keep the deliberately invalid examples commented.
  3. Run dotnet run or press Ctrl+F5. Compare the result with the expected output.
using System;

public class Learner
{
    public int Id { get; init; }
    public string Name { get; set; } = "";
    public string Course { get; set; } = "";
    public Learner() => Console.WriteLine("Constructor executed");
}

public class Program
{
    public static void Main()
    {
        var learner = new Learner
        {
            Id = 101,
            Name = "Anu",
            Course = "C#"
        };
        Console.WriteLine($"{learner.Id} | {learner.Name} | {learner.Course}");
        learner.Name = "Anu Kumar"; // set allows later changes.
        // learner.Id = 102; // init does not allow this later assignment.
    }
}

Expected output

Constructor executed
101 | Anu | C#

How the code works

  1. new Learner creates an instance and invokes its constructor.
  2. The braces after new contain property assignments, not a class definition.
  3. Id can be initialized because it has an init accessor.
  4. Name remains writable afterward because it has set.

Benefit

Makes initialization readable and works with both normal setters and init accessors.

Limitation and how to handle it

An initializer does not bypass validation or guarantee that all important properties were set. Use constructors or required members when the model needs stronger construction requirements.

Common mistake: Separate assignments with commas inside the initializer. You cannot assign a property with an inaccessible setter. An initializer does not replace the constructor call.

Short oral questions with answers

Can a sealed class implement an interface?

Yes. Sealed prevents subclassing; it does not prevent implementing an interface.

Does a get-only interface property make the object immutable?

No. It limits what is accessible through that interface. The concrete object may expose a setter or a method that changes the value.

Can a class implement multiple interfaces?

Yes. A class has at most one direct class base but may implement multiple interfaces.

Does partial mean inheritance?

No. Partial declarations are combined into the same type during compilation.

Does an extension method change the original type?

No. It provides a static method with convenient receiver syntax.

Does an object initializer skip the constructor?

No. The constructor runs first; initializer assignments follow.

Can an indexer use a string key?

Yes. The parameter type and lookup behavior are chosen by the class designer.

Why use a generic collection rather than List<object>?

A generic collection preserves the element type for callers and catches mismatched values at compile time.
