LESSON 02

The architecture of a class

A class defines a reference type: its state and behavior. An object is an instance of that class. A class declaration can contain fields, properties, constructors, methods, events, indexers, and nested types. We start with the first five.

using System;

namespace Training;

public class Course
{
    private decimal _fee;                   // Field: internal state
    public static int CreatedCount { get; private set; } // Shared counter
    public string Title { get; }            // Property: controlled access
    public decimal Fee => _fee;             // Read-only public view

    public Course(string title, decimal fee) // Constructor: initial state
    {
        if (string.IsNullOrWhiteSpace(title))
            throw new ArgumentException("Title is required.", nameof(title));
        if (fee < 0)
            throw new ArgumentOutOfRangeException(nameof(fee));
        Title = title;
        _fee = fee;
        CreatedCount++;
    }

    public void Display()                   // Method: behavior
        => Console.WriteLine($"{Title}: {_fee}");
}

public static class Program
{
    public static void Main()
    {
        Course course = new Course("C#", 5000m);
        course.Display();
        Console.WriteLine(Course.CreatedCount);
    }
}

Expected output

C#: 5000
1

namespace groups names. public class Course declares the type. A field stores data; a property exposes it under rules. A constructor establishes valid starting values. A method performs an action. m makes a numeric literal a decimal, useful for monetary calculations.

LESSON 03

Instance, class (static), local and reference variables

These terms describe different aspects of a variable. “Instance/static/local” describes where state belongs. “Value/reference” describes the kind of value stored. A reference variable can be a local variable, an instance field, or a static field.

LESSON 04

Structures: small values with value semantics

A struct is a value type. Assigning it normally copies the struct's fields. Use a small struct for a value such as a coordinate, measurement, or fee amount. A class is often appropriate for an entity with identity such as a learner account.

using System;

public struct Score
{
    public int Value { get; set; }
}

public static class Program
{
    public static void Main()
    {
        Score original = new Score { Value = 70 };
        Score copy = original;
        copy.Value = 90;
        Console.WriteLine(original.Value);
        Console.WriteLine(copy.Value);
    }
}
70
90

Step through the assignment: copy receives a separate value. Mutable structs are used here to make copying visible; prefer immutable values in application designs when practical.

Featureclassstruct
Type categoryReference typeValue type
Ordinary assignmentCopies object referenceCopies value (fields)
InheritanceCan derive from one classCannot derive from a user-defined class/struct
InterfacesCan implement interfacesCan implement interfaces
Can be null?Yes; nullable annotations describe intentUse Score? for nullable value
FinalizerCan declare oneCannot declare one

Important: a struct containing a reference field copies that reference, not the entire referenced object. If a struct contains a List<int>, two copies can still refer to the same list. Structs can be fields inside heap objects and can be boxed into objects.

default(Score) produces zero-initialized fields. Modern C# supports explicit public parameterless struct constructors, but default(T) and array element initialization still produce the zero-initialized value. Do not assume every creation path runs a custom struct constructor.

LESSON 05

Enums: named choices instead of magic numbers

An enum represents named integral constants. It makes a small, stable set of choices clear, such as Draft, Published, and Archived. By default its underlying type is int.

using System;

public enum CourseStatus
{
    Draft = 0,
    Published = 1,
    Archived = 2
}

public static class Program
{
    public static void Main()
    {
        CourseStatus status = CourseStatus.Published;
        Console.WriteLine(status);
        Console.WriteLine((int)status);
        Console.WriteLine(status == CourseStatus.Published
            ? "Students can enroll" : "Enrollment closed");
        CourseStatus incoming = (CourseStatus)99;
        Console.WriteLine(Enum.IsDefined(typeof(CourseStatus), incoming));
    }
}
Published
1
Students can enroll
False

The cast to 99 compiles even though 99 has no named member. Validate external input. The default enum value is zero even when zero has no declared name, so define a sensible zero member when possible. Use explicit values for persisted or exchanged enums so reordering members does not change stored meanings.

Optional extension: [Flags] enums represent combinations; assign individual flags powers of two (1, 2, 4...). Enum.IsDefined alone is not a general validator for every valid flags combination.

LESSON 06

Access modifiers: who may use a member?

Access modifiers restrict which code can use a type or member. An assembly is a compiled unit such as a DLL; a namespace is a naming group. Two classes in different namespaces can still be in the same assembly.

ModifierSame classUnrelated class in same assemblyDerived class in same assemblyDerived class in another assemblyUnrelated class in another assembly
publicYesYesYesYesYes
privateYesNoNoNoNo
protectedYesNoYesYes*No
internalYesYesYesNoNo
protected internalYesYesYesYes*No
private protectedYesNoYesNoNo

* For protected access through an instance in derived code, the receiver must be the derived type or a subtype; an arbitrary base-class reference is insufficient. This matrix describes ordinary member access, without friend assemblies or nested-type exceptions, and assumes the containing type is accessible.

protected internal means same assembly OR derived access. private protected means derived access AND same assembly.
using System;

public class AccessBase
{
    private int secret = 10;
    public int PublicValue = 20;
    protected int ProtectedValue = 30;
    internal int InternalValue = 40;
    protected internal int EitherValue = 50;
    private protected int BothValue = 60;
    public int ReadSecret() => secret;
}

public class AccessChild : AccessBase
{
    public void Show()
    {
        Console.WriteLine(ProtectedValue);
        Console.WriteLine(EitherValue);
        Console.WriteLine(BothValue); // Works: derived and same assembly
        // Console.WriteLine(secret); // Does not compile: private
    }
}

public static class Program
{
    public static void Main()
    {
        AccessBase item = new AccessBase();
        Console.WriteLine(item.PublicValue);
        Console.WriteLine(item.InternalValue);
        Console.WriteLine(item.EitherValue);
        Console.WriteLine(item.ReadSecret());
        new AccessChild().Show();
        // Console.WriteLine(item.ProtectedValue); // Not derived code
    }
}

Two-project trainer lab

  1. Create a solution with a class library Training.Core and console project Training.App.
  2. Put AccessBase in the library. Add a project reference from App to Core.
  3. Put AccessChild in App. Keep the base class public.
  4. Try each member individually. BothValue now fails even in the child, because App is another assembly. InternalValue fails as well. ProtectedValue and EitherValue work through the child instance.
  5. In an unrelated App class, only public members work. In an unrelated Core class, internal and protected internal also work.

Defaults: a top-level class/struct/enum is internal when its access modifier is omitted. Class fields and methods default to private. Top-level types do not accept private or protected. A public member cannot be used through an inaccessible containing type. A property can expose a getter while restricting its setter, for example public int Id { get; private set; }.

new, static, abstract, virtual, and override serve other purposes; none is an access modifier.

LESSON 07

Constructors: initialize valid objects

A constructor has the type's name and no return type. Instance constructors run as objects are created. Overloaded constructors offer different creation inputs. this(...) delegates to another constructor in the same type; base(...) selects a base constructor.

using System;

public class Enrollment
{
    public string Learner { get; }
    public decimal Fee { get; }
    public static string Institute { get; }

    static Enrollment()
    {
        Institute = "EduSync";
        Console.WriteLine("Static initialization");
    }

    public Enrollment() : this("Guest", 0m) { }
    public Enrollment(string learner, decimal fee)
    {
        if (fee < 0) throw new ArgumentOutOfRangeException(nameof(fee));
        Learner = learner;
        Fee = fee;
        Console.WriteLine($"Created: {Learner}");
    }
}

public static class Program
{
    public static void Main()
    {
        Enrollment first = new Enrollment();
        Enrollment second = new Enrollment("Anu", 5000m);
        Console.WriteLine(Enrollment.Institute);
    }
}
Static initialization
Created: Guest
Created: Anu
EduSync

The parameterless constructor reuses validation through this. The static constructor has no access modifier or parameters, cannot be called explicitly, and executes at most once per type initialization. Here it runs before the first instance is created.

If a nonstatic, nonabstract class declares no instance constructor, the compiler supplies a public parameterless one. Once you declare a constructor, the compiler does not also supply that one. Abstract classes receive a protected default constructor instead. Constructors are not inherited, cannot be virtual, and cannot be overridden.

Constructor-body order in a simple inheritance example: the selected base constructor body runs before the derived constructor body. Field initializers have their own language-defined order, so avoid using this simple rule as a complete account of all initialization.

LESSON 08

Destructors, finalizers and the garbage collector

The GC reclaims managed memory that is no longer reachable from application roots. Leaving a variable's scope does not promise immediate collection. Assigning one reference to null does not make an object collectible if other reachable references still lead to it.

Reachable object
keep using it
No reachable path
eligible for collection
A later GC
may reclaim memory

Generations 0, 1 and 2 help the GC focus on shorter-lived allocations. Objects surviving collections may be promoted. These details optimize collection; they are not a schedule that application code should rely on.

public class NativeWrapper
{
    ~NativeWrapper()
    {
        // Finalizer syntax demonstration only.
        // Real native ownership normally uses SafeHandle + IDisposable.
    }
}

The ~NativeWrapper() syntax is commonly called a destructor. In C# it is a finalizer: there are no parameters, access modifiers, or direct calls. Its timing is nondeterministic, it adds overhead, and execution is not guaranteed at process shutdown. Do not add finalizers to ordinary business classes or use them to save essential business data.

Practical resource cleanup: using

using System;
using System.IO;

public static class Program
{
    public static void Main()
    {
        using (StreamWriter writer = new StreamWriter("attendance.txt"))
        {
            writer.WriteLine("Anu,Present");
        } // Dispose runs here, including when the block exits by exception.
        Console.WriteLine(File.ReadAllText("attendance.txt").Trim());
    }
}
Anu,Present

The program creates or replaces attendance.txt in its working directory. Dispose releases the writer's resources promptly. It does not mean the managed StreamWriter object has already been collected.

MechanismPurposeTiming
ConstructorInitialize an objectDuring construction
Dispose / usingRelease owned resourcesDeterministic at the explicit call/scope exit
FinalizerFallback for unmanaged resource ownership when neededRuntime-controlled; no reliable schedule
GCReclaim unreachable managed memoryRuntime-controlled

Prefer existing disposable library types and SafeHandle for native handles. Normally let the runtime decide when to collect; do not put GC.Collect() in regular business logic. Memory can still grow if you retain objects in static lists, event subscriptions, or unbounded caches.

Trainer exercise: stop inside and after the using block. Explain that closing a file and reclaiming object memory solve different problems.

.NET Base Class Library: reuse common building blocks

The .NET Base Class Library (BCL) provides reusable types for common work. C# is the language, the CLR executes managed code, and the libraries provide APIs. The broader .NET libraries also include facilities beyond the narrow BCL label.

using System;
using System.Collections.Generic;
using System.Linq;

public static class Program
{
    public static void Main()
    {
        List<decimal> fees = new List<decimal> { 3000m, 5000m, 8000m };

LESSON 10

Inheritance: express an is-a relationship

A derived class specializes a base class. An OnlineCourse is a Course; a Course has a collection of enrollments. Use inheritance for the first relationship and composition for the second.

using System;

public class Course
{
    public string Title { get; }
    public Course(string title) { Title = title; }
    public void ShowTitle() => Console.WriteLine(Title);
}

public class OnlineCourse : Course
{
    public string Platform { get; }
    public OnlineCourse(string title, string platform) : base(title)
        { Platform = platform; }
    public void Join() => Console.WriteLine($"Join using {Platform}");
}

public static class Program
{
    public static void Main()
    {
        OnlineCourse course = new OnlineCourse("C#", "Teams");
        course.ShowTitle();
        course.Join();
        Course baseView = course; // Upcast: still the same object
        baseView.ShowTitle();
    }
}
C#
Join using Teams
C#

C# permits one direct base class, while a class can implement multiple interfaces. Private base state still belongs to the base portion of the object, but derived code cannot access it directly. Constructors are not inherited. A sealed class prevents further derivation.

Trainer prompt: “Does assigning course to baseView create another course?” Answer: no. It copies a reference and changes the members available through that variable's declared type.

LESSON 11

Abstract classes: common code plus required behavior

An abstract class cannot be instantiated directly. It can hold state, constructors, implemented methods, and abstract members. Abstract methods declare a contract without a body; a concrete derived class must supply implementations for the remaining abstract members.

using System;

public abstract class Course
{
    public string Title { get; }
    protected Course(string title) { Title = title; }
    public void Describe() => Console.WriteLine(Title);
    public abstract decimal CalculateFee();
}

public class RecordedCourse : Course
{
    public RecordedCourse(string title) : base(title) { }
    public override decimal CalculateFee() => 2000m;
}

public static class Program
{
    public static void Main()
    {
        Course course = new RecordedCourse("C# Basics");
        course.Describe();
        Console.WriteLine(course.CalculateFee());
        // Course invalid = new Course("C#"); // Cannot instantiate abstract type
    }
}
C# Basics
2000

The constructor in Course still runs as part of constructing RecordedCourse. abstract is appropriate when every course needs its own fee rule but shares common data. Use an interface when you chiefly need a capability contract across otherwise unrelated types; choose an abstract class when shared instance state and implementation are central.

Practice: create LiveCourse with a fee of 5000. Put both concrete objects in a Course[] and call CalculateFee in a loop.

LESSON 12

Method overloading: same name, different inputs

Overloading offers multiple signatures for one conceptual operation. Overload selection ordinarily happens at compile time from the method arguments and their compile-time types; dynamic binding is a separate advanced case.

using System;

public class FeeCalculator
{
    public decimal Calculate(decimal fee) => fee;
    public decimal Calculate(decimal fee, int learners) => fee * learners;
    public decimal Calculate(decimal fee, decimal discountPercent)
        => fee * (1m - discountPercent / 100m);
}

public static class Program
{
    public static void Main()
    {
        FeeCalculator calculator = new FeeCalculator();
        Console.WriteLine(calculator.Calculate(5000m));
        Console.WriteLine(calculator.Calculate(5000m, 2));
        Console.WriteLine(calculator.Calculate(5000m, 10m));
    }
}
5000
10000
4500.0

2 is int, so it selects learner count. 10m is decimal, so it selects discount percent. Return type alone, parameter names alone, and static versus instance alone do not distinguish overloads. Production methods should validate business ranges.

Overloading two parameters with different meanings can surprise callers. For a business API, names such as CalculateGroupFee and ApplyDiscount can be clearer. This example makes overload selection visible.

LESSON 13

Method overriding and method hiding: predict dispatch

Overriding changes inherited virtual behavior for the same polymorphic operation. Hiding declares another member that conceals a base member during lookup. These mechanisms produce different results when a variable has the base type.

using System;

public class BaseCourse
{
    public virtual void Teach() => Console.WriteLine("Base teaching");
    public void Describe() => Console.WriteLine("Base description");
}

public class LiveCourse : BaseCourse
{
    public override void Teach() => Console.WriteLine("Live teaching");
    public new void Describe() => Console.WriteLine("Live description");
}

public static class Program
{
    public static void Main()
    {
        LiveCourse derived = new LiveCourse();
        BaseCourse baseView = derived;
        derived.Teach();
        baseView.Teach();
        derived.Describe();
        baseView.Describe();
    }
}
Live teaching
Live teaching
Live description
Base description

Teach uses the runtime object's overridden implementation through both variables. Describe is a nonvirtual hidden member: member selection follows the variable's compile-time type. new explicitly acknowledges hiding; omitting it generally produces a warning and does not turn hiding into overriding.

A base member must be virtual, abstract, or an overridable override for a derived member to override it. You cannot override a static method, constructor, or nonvirtual method. An override cannot arbitrarily change accessibility; cross-assembly protected internal overrides have a special protected accessibility rule. base.Teach() inside an override explicitly calls the base implementation. sealed override stops further overriding.

PurposeOffer different input signaturesSpecialize virtual behaviorDeclare a separate member with same name

The two roles of new: new LiveCourse() constructs an object. public new void Describe() declares hiding. Neither use grants access.

LESSON 14

Operator overloading: meaningful operations on your types

Operator overloading lets a user-defined type define an operator's behavior. For example, adding two fee amounts can return a new fee amount. Keep the meaning predictable; use named methods for operations that would surprise readers.

using System;

public readonly struct FeeAmount
{
    public decimal Value { get; }
    public FeeAmount(decimal value) { Value = value; }

    public static FeeAmount operator +(FeeAmount left, FeeAmount right)
        => new FeeAmount(left.Value + right.Value);
}

public static class Program
{
    public static void Main()
    {
        FeeAmount tuition = new FeeAmount(5000m);
        FeeAmount lab = new FeeAmount(500m);
        FeeAmount total = tuition + lab;
        Console.WriteLine(total.Value);
    }
}
5500

The + operator here is a public static method, one of its operands is the containing type, and it returns a new value. The readonly struct prevents accidental state changes after construction.

You cannot invent new operator symbols or change operator precedence or operand count. Operators such as ==/!= require paired definitions. Equality designs should also keep Equals and GetHashCode consistent. Real multi-currency amounts must check currency compatibility; this example assumes all values are in the same currency.

Version note: the traditional public static binary operator form above is supported across the targeted versions. C# 14 also supports instance compound-assignment operators and instance increment/decrement operators; the blanket claim that every user-defined operator must always be static is no longer accurate.

Practice: implement subtraction for FeeAmount. Decide and document whether negative results are permitted before adding validation.

LESSON 15

Integrated lab: build the course fee console app

Replace Program.cs with the complete program below. It combines the concepts without a database or external packages. A finalizer is intentionally excluded: these business objects do not own unmanaged resources.

using System;
using System.Collections.Generic;
using System.Globalization;
using System.Linq;

public enum CourseStatus { Draft = 0, Published = 1, Archived = 2 }

public readonly struct FeeAmount
{
    public decimal Value { get; }
    public FeeAmount(decimal value)
    {
        if (value < 0) throw new ArgumentOutOfRangeException(nameof(value));
        Value = value;
    }
    public static FeeAmount operator +(FeeAmount left, FeeAmount right)
        => new FeeAmount(left.Value + right.Value);
}

public abstract class Course
{
    private readonly decimal _baseFee;
    public static int CreatedCount { get; private set; }
    public string Title { get; }
    public CourseStatus Status { get; private set; }
    protected decimal BaseFee => _baseFee;
    internal string Code { get; }
    protected internal string Institute => "EduSync";
    private protected decimal LabFee => 500m;

    protected Course(string title, decimal baseFee, string code)
    {
        if (string.IsNullOrWhiteSpace(title))
            throw new ArgumentException("Title is required.", nameof(title));
        if (baseFee < 0) throw new ArgumentOutOfRangeException(nameof(baseFee));
        Title = title;
        _baseFee = baseFee;
        Code = code;
        Status = CourseStatus.Draft;
        CreatedCount++;
    }

    public void Publish() => Status = CourseStatus.Published;
    public abstract FeeAmount CalculateFee();
    public FeeAmount CalculateFee(int learners)
    {
        if (learners < 1) throw new ArgumentOutOfRangeException(nameof(learners));
        return new FeeAmount(CalculateFee().Value * learners);
    }
    public virtual string Delivery() => "General delivery";
    public string Describe() => "Base course view";
}

public class LiveCourse : Course
{
    public LiveCourse(string title, decimal baseFee)
        : base(title, baseFee, "LIVE") { }
    public override FeeAmount CalculateFee()
        => new FeeAmount(BaseFee) + new FeeAmount(LabFee);
    public override string Delivery() => "Live instructor session";
    public new string Describe() => "Live course view";
    public string GetInstitute() => Institute;
}

public class RecordedCourse : Course
{
    public RecordedCourse(string title) : this(title, 2000m) { }
    public RecordedCourse(string title, decimal baseFee)
        : base(title, baseFee, "REC") { }
    public override FeeAmount CalculateFee() => new FeeAmount(BaseFee);
    public override string Delivery() => "Recorded videos";
}

public static class Program
{
    public static void Main()
    {
        // Stable decimal formatting for the documented output.
        CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;
        LiveCourse live = new LiveCourse("C# Live", 5000m);
        RecordedCourse recorded = new RecordedCourse("C# Recorded");
        live.Publish();
        recorded.Publish();
        Course alias = live;

        Console.WriteLine($"Same object: {ReferenceEquals(live, alias)}");
        Console.WriteLine($"Count: {Course.CreatedCount}");
        Console.WriteLine($"Status: {live.Status}");
        Console.WriteLine($"Override: {alias.Delivery()}");
        Console.WriteLine($"Hidden via derived: {live.Describe()}");
        Console.WriteLine($"Hidden via base: {alias.Describe()}");
        Console.WriteLine($"One learner: {live.CalculateFee().Value}");
        // Use the base-typed variable to expose both base overload signatures.
        Console.WriteLine($"Three learners: {alias.CalculateFee(3).Value}");
        Console.WriteLine($"Internal code: {live.Code}");
        Console.WriteLine($"Institute: {live.GetInstitute()}");

        List<Course> courses = new List<Course> { live, recorded };
        foreach (Course course in courses.Where(c => c.Status == CourseStatus.Published))
            Console.WriteLine($"{course.Title}: {course.CalculateFee().Value}");
        FeeAmount combined = live.CalculateFee() + recorded.CalculateFee();
        Console.WriteLine($"Combined fees: {combined.Value}");
    }
}

Review questions with answers

Is a reference variable always a class/static variable?

No. Reference describes the stored value category. Static describes association with a type. A local variable can hold a reference.

Can a public method expose a private field safely?

Yes, by returning a permitted view or validated operation. Public accessibility does not itself expose every private member.

Does protected internal require both conditions?

No. It permits same-assembly access OR protected derived access. Private protected requires the intersection.

Can return type alone distinguish overloads?

No. int Read() and string Read() cannot coexist solely as return-type overloads.

Can an abstract class have a constructor?

Yes. It initializes the base portion of a derived object.

What selects a virtual override?

After compile-time member lookup and overload resolution, virtual dispatch selects the implementation for the runtime object.

Does new mean public?

No. As a member modifier it acknowledges hiding; accessibility is declared separately.

Does using force garbage collection?

No. It arranges Dispose calls. GC separately manages reachable managed memory.

Can a struct contain a reference?

Yes. Copying that struct copies the reference field, so referenced state can remain shared.

Why not implement a finalizer in every class?

Ordinary managed business objects do not need one. Finalizers introduce nondeterministic cleanup and additional GC work.
