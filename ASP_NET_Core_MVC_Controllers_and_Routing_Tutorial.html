01 · Introduction to Controller

A controller is a C# class that handles incoming HTTP requests, coordinates business logic and returns a response. MVC separates Model (data), View (presentation) and Controller (request handling). Keep controllers thin: delegate business logic to services.

Browser → Routing → Controller → Action → Model / Service → View or JSON → Browser
ComponentResponsibility
ModelData and validation
ViewRazor HTML presentation
ControllerSelect action and coordinate response
RoutingMatch URL and HTTP method to endpoint

02 · Creating Controller

In Visual Studio 2022: Create a new project → ASP.NET Core Web App (Model-View-Controller) → EmployeePortal → .NET 8. Alternatively use CLI:

dotnet new mvc -n EmployeePortal -f net8.0
cd EmployeePortal
dotnet run

Create Controllers/EmployeesController.cs (right-click Controllers → Add → Controller → MVC Controller - Empty).

using Microsoft.AspNetCore.Mvc;
namespace EmployeePortal.Controllers;
public class EmployeesController : Controller
{
    public IActionResult Index() => View();
    public IActionResult Welcome() => Content("Welcome to Employee Portal");
}

Create Views/Employees/Index.cshtml:

<h1>Employee Management Portal</h1>
<a asp-controller="Employees" asp-action="Welcome">Welcome</a>

Open the local URL shown in the console, followed by /Employees or /Employees/Welcome. Controller suffix is omitted from the URL.

03 · Introduction to Routing

Routing maps an incoming request to an endpoint. Route values identify the controller, action and optional parameters. Routing is not a physical folder lookup.

GET /Employees/Details/101 → controller=Employees → action=Details → id=101

Unmatched routes generally return 404; unsupported HTTP methods on matched endpoints may return 405.

04 · Transfer Data

Use a strongly typed view model for structured data. ViewData and ViewBag share the same dictionary; TempData survives into a later request until read (normally cookie-backed). Session requires explicit configuration.

TechniqueLifetime / use
ViewDataCurrent request; dictionary
ViewBagCurrent request; dynamic access
View modelCurrent response; compile-time typing
TempDataAcross redirect; short-lived notification
Query string / routeClient-visible values; validate all input
public IActionResult Transfer()
{
    ViewData["Department"] = "IT";
    ViewBag.Message = "Welcome";
    return View(new List<string> { "Anu", "Ravi" });
}
public IActionResult SaveMessage()
{
    TempData["Message"] = "Employee saved";
    return RedirectToAction(nameof(Index));
}

Insert these methods inside EmployeesController. Create Views/Employees/Transfer.cshtml:

@model List<string>
<h2>@ViewBag.Message</h2>
<p>@ViewData["Department"]</p>
@foreach (var name in Model) { <p>@name</p> }

Add to Index.cshtml to display the flash message:

<p>@TempData["Message"]</p>

SaveMessage is only a notification demo, not a real database write. Real state-changing actions should use POST with antiforgery protection.

05 · Conventional Routing

A central pattern defines how URLs map to controllers. Replace the route mapping in Program.cs with the following complete minimal MVC configuration (development lab):

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllersWithViews();
var app = builder.Build();
app.UseStaticFiles();
app.UseRouting();
app.UseAuthorization();
app.MapControllerRoute(
    name: "areas",
    pattern: "{area:exists}/{controller=Home}/{action=Index}/{id?}");
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");
app.Run();
URLTarget
/Home.Index
/EmployeesEmployees.Index
/Employees/Details/101Employees.Details(101)

Defaults are indicated by = and optional parameters by ?. Put specific conventional routes before general ones.

06 · Attribute Based Routing

Declare route templates on controllers and actions. HTTP verb attributes can both constrain the request method and define a route. Add a separate controller:

using Microsoft.AspNetCore.Mvc;
namespace EmployeePortal.Controllers;
[Route("staff")]
public class StaffController : Controller
{
    [HttpGet("")]
    public IActionResult List() => Content("Staff list");

    [HttpGet("{id:int}")]
    public IActionResult Details(int id) => Ok(new { id, name = "Anu" });
}

Test GET /staff and GET /staff/101. /staff/abc does not match the integer constraint. Attribute-routed actions are not reachable through the conventional route by default. Route constraints are for matching, not business validation.

07 · URL Routing and URL Generation

URL routing is the general process of matching URLs; conventional and attribute routing are two ways to define routes. Generate links instead of hardcoding paths.

<a asp-controller="Employees" asp-action="Details" asp-route-id="101">Details</a>
<a href="@Url.Action("Details", "Employees", new { id = 101 })">Details</a>

Use these in a Razor view. The MVC template includes Tag Helpers via Views/_ViewImports.cshtml. URL generation depends on configured routes and ambient values.

08 · Endpoint Routing

Endpoint routing is the ASP.NET Core infrastructure that matches requests and makes endpoint metadata available to middleware such as authorization. UseRouting selects an endpoint; endpoint execution invokes the action after applicable middleware.

HTTP request → UseRouting (match endpoint) → Authentication if configured → Authorization → Endpoint execution → Response
app.UseRouting();
app.UseAuthorization();
app.MapControllerRoute("default", "{controller=Home}/{action=Index}/{id?}");

MapControllers() maps attribute-routed controllers; MapControllerRoute() registers MVC conventional routes and supports attribute-routed actions as well. Minimal hosting can insert routing automatically, but explicit placement is useful for teaching middleware order.

09 · Areas

Areas organize large applications into independent functional modules, such as Admin and HR. They are not security boundaries; authorization must be configured separately.

EmployeePortal → Areas → Admin → Controllers / Views → HomeController / Index.cshtml
using Microsoft.AspNetCore.Mvc;
namespace EmployeePortal.Areas.Admin.Controllers;
[Area("Admin")]
public class HomeController : Controller
{
    public IActionResult Index() => View();
}

Save as Areas/Admin/Controllers/HomeController.cs and create Areas/Admin/Views/Home/Index.cshtml:

<h1>Admin Dashboard</h1>

The areas route in Program.cs enables /Admin/Home/Index. To generate links from a regular view:

<a asp-area="Admin" asp-controller="Home" asp-action="Index">Admin</a>
<a asp-area="" asp-controller="Employees" asp-action="Index">Employees</a>

For Tag Helpers within Area views, add Areas/_ViewImports.cshtml with @addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers.

10 · Controller Actions

An action is a public controller method eligible for request handling. Use HTTP method attributes to distinguish read and write operations. Mark helper methods private or [NonAction]. Insert these methods into EmployeesController:

[HttpGet]
public IActionResult Create() => View();

[HttpPost]
[ValidateAntiForgeryToken]
public IActionResult Create(string name)
{
    if (string.IsNullOrWhiteSpace(name))
    {
        ModelState.AddModelError("name", "Name is required");
        return View();
    }
    TempData["Message"] = $"Received {name}";
    return RedirectToAction(nameof(Index));
}
[NonAction]
public string FormatName(string name) => name.Trim();

Create Views/Employees/Create.cshtml:

<form asp-action="Create" method="post">
    <div asp-validation-summary="All"></div>
    <label for="name">Name</label>
    <input id="name" name="name" />
    <button type="submit">Submit</button>
</form>

Form Tag Helper generates an antiforgery token for this POST form. This lab does not persist employee data. GET displays the form; POST validates and redirects (Post/Redirect/Get).

11 · Passing Values to Actions

Model binding converts values from route, query string, form and other configured sources into parameters or models. Specify binding source explicitly where useful.

public IActionResult Details([FromRoute] int id)
{
    if (id <= 0) return BadRequest("Invalid ID");
    return Content($"Employee ID: {id}");
}
public IActionResult Search([FromQuery] string? name)
    => Content($"Search: {name}");
RequestBound value
/Employees/Details/101id = 101
/Employees/Search?name=Anuname = Anu
POST /Employees/Create (form name=Anu)name = Anu

For complex forms, bind a view model and check ModelState.IsValid. Never trust client-supplied IDs or values for access decisions.

12 · Action Return Types

IActionResult supports multiple result types from one action. ActionResult<T> is useful for typed API responses. Task<IActionResult> is suitable for asynchronous I/O.

Return helperResult / status
View(model)ViewResult; HTML, usually 200
Content("Hi")ContentResult; text
Json(data)JsonResult; JSON
Ok(data)ObjectResult; 200
NotFound()404
BadRequest()400
RedirectToAction("Index")302 redirect
File(bytes, "text/plain")File response
NoContent()204
public IActionResult ResultDemo(int id)
{
    if (id <= 0) return BadRequest();
    if (id != 101) return NotFound();
    return Json(new { id, name = "Anu" });
}

Try /Employees/ResultDemo?id=101, id=0 and id=999. Use browser developer tools → Network to inspect status, headers and body.

Interview questions

What is a controller?

A request-handling class that coordinates logic and returns action results.

Conventional vs attribute routing?

Central patterns versus templates attached directly to actions/controllers.

ViewBag vs TempData?

ViewBag is current request; TempData can survive a redirect.

What is endpoint routing?

The infrastructure for endpoint selection and execution with metadata.

What is an Area?

A logical MVC module with separate controllers and views.

What is model binding?

Mapping request values to action parameters and models.

IActionResult vs ActionResult<T>?

IActionResult allows varied results; ActionResult<T> also describes a typed API payload.

Why Post/Redirect/Get?

Avoid accidental form resubmission on refresh.

Why use antiforgery?

To mitigate cross-site request forgery for applicable browser form requests.

404 vs 405?

404 means no matching resource/endpoint; 405 indicates method not allowed for the matched endpoint.
