02. Why files are needed

Variables store data in memory. When the process exits, that memory is lost. Files provide persistent storage for reports, logs, configuration and exported data.

03. File paths and directories

A path identifies a file or directory. A relative path is resolved against the current working directory; an absolute path identifies a full location. Use Path.Combine for portable paths.

Create a training directory

Create a folder safely even if it already exists.

string folder = Path.Combine(Environment.CurrentDirectory, "LabData");
Directory.CreateDirectory(folder);
string path = Path.Combine(folder, "notes.txt");
Console.WriteLine(Path.GetFileName(path));
Console.WriteLine(Directory.Exists(folder));

Expected output

notes.txt
True

Directory.CreateDirectory creates missing parent directories. Path.Combine constructs the path; it does not create a file.

Files created by these labs are under the current working directory unless a different path is specified. Use disposable practice files, not production data.

04. File class: read, write and append

The static File class provides convenient operations for small files.

WriteAllText
→
📄 notes.txt
→
ReadAllText

Write and read text

Write a message, then read it back.

string path = "notes.txt";
File.WriteAllText(path, "Welcome to C#");
string text = File.ReadAllText(path);
Console.WriteLine(text);

Expected output

Welcome to C#

WriteAllText creates or overwrites the file and closes it automatically. ReadAllText loads the entire content into a string.

Append without deleting previous content

Add a second line.

string path = "activity.txt";
File.WriteAllText(path, "Login" + Environment.NewLine);
File.AppendAllText(path, "Logout" + Environment.NewLine);
Console.Write(File.ReadAllText(path));

Expected output

Login
Logout

AppendAllText adds content at the end; unlike WriteAllText, it retains existing content.

Read multiple lines

Process an array of lines.

File.WriteAllLines("marks.txt", new[] { "85", "90", "75" });
foreach (string line in File.ReadLines("marks.txt"))
    Console.WriteLine(int.Parse(line));

Expected output

85
90
75

ReadLines enumerates lines lazily. ReadAllLines reads them all into an array. Use TryParse for untrusted input.

05. FileInfo and DirectoryInfo

Inspect and copy a file

Use instance-based APIs for metadata and operations.

File.WriteAllText("source.txt", "CSharp");
FileInfo info = new FileInfo("source.txt");
Console.WriteLine(info.Name);
Console.WriteLine(info.Length);
info.CopyTo("backup.txt", overwrite: true);
DirectoryInfo folder = new DirectoryInfo(".");
Console.WriteLine(folder.Exists);

Expected output

source.txt
6
True

FileInfo exposes metadata such as Length, Name and LastWriteTime. DirectoryInfo exposes directory metadata. Call Refresh when cached metadata may be stale.

File.Move("backup.txt", "renamed.txt", overwrite: true);
File.Delete("renamed.txt");
Delete removes a file; do not run destructive commands against important paths. Directory.Delete(path, recursive: true) removes a tree.

06. Streams: StreamReader and StreamWriter

A stream represents a sequence of bytes. Text reader/writer classes convert between bytes and characters. Use them for incremental processing.

Text
→
StreamWriter
→
FileStream
→
Disk

Write and read line by line

Use using to release file handles even if exceptions occur.

using (StreamWriter writer = new StreamWriter("students.txt"))
{
    writer.WriteLine("Anu,85");
    writer.WriteLine("Ravi,90");
}
using (StreamReader reader = new StreamReader("students.txt"))
{
    string? line;
    while ((line = reader.ReadLine()) != null)
        Console.WriteLine(line);
}

Expected output

Anu,85
Ravi,90

The writer is disposed before the reader opens the file. ReadLine returns null at end of file. using ensures Dispose runs.

07. Binary files and FileStream

Write typed binary data

BinaryWriter stores typed values, not human-readable text.

using (var writer = new BinaryWriter(File.Create("product.bin")))
{
    writer.Write(101);
    writer.Write("Pen");
    writer.Write(25.50m);
}
using (var reader = new BinaryReader(File.OpenRead("product.bin")))
{
    Console.WriteLine(reader.ReadInt32());
    Console.WriteLine(reader.ReadString());
    Console.WriteLine(reader.ReadDecimal());
}

Expected output

101
Pen
25.50 (format may vary by culture)

Read values in the same order and type used to write them. BinaryWriter and BinaryReader are useful for a known binary format.

Copy bytes using FileStream

Copy data without loading the whole file into memory.

File.WriteAllText("original.txt", "Sample");
using (FileStream input = File.OpenRead("original.txt"))
using (FileStream output = File.Create("copy.txt"))
    input.CopyTo(output);
Console.WriteLine(File.ReadAllText("copy.txt"));

Expected output

Sample

CopyTo streams data through a buffer. File.Create overwrites an existing destination.

08. JSON serialization and deserialization

Serialization converts an object into a format that can be stored or transmitted. Deserialization reconstructs an object from that format.

C# object
→
Serialize
→
📄 JSON
→

C# object

Save an employee object

Use System.Text.Json to persist structured data.

using System.Text.Json;
var employee = new Employee(101, "Anu", 45000);
string json = JsonSerializer.Serialize(employee,
    new JsonSerializerOptions { WriteIndented = true });
File.WriteAllText("employee.json", json);
Employee? result = JsonSerializer.Deserialize<Employee>(
    File.ReadAllText("employee.json"));
Console.WriteLine(result?.Name);
record Employee(int Id, string Name, decimal Salary);

Expected output

Anu

Serialize creates JSON text. Deserialize maps it back to the record. JSON property names and types must be compatible.

XML is another structured format (XmlSerializer). Avoid BinaryFormatter: it is unsafe and obsolete. BinaryReader/BinaryWriter are different APIs.

09. File errors and safe handling

Handle missing files and access errors

A file may be missing, locked, inaccessible or on an unavailable drive.

try
{
    Console.WriteLine(File.ReadAllText("missing-file-demo.txt"));
}
catch (FileNotFoundException)
{
    Console.WriteLine("File not found.");
}
catch (UnauthorizedAccessException)
{
    Console.WriteLine("Access denied.");
}
catch (IOException ex)
{
    Console.WriteLine($"I/O error: {ex.Message}");
}

Expected output

File not found. (if the file does not exist)

Catch specific exceptions before broader ones. File.Exists can help with checks, but a file can disappear after the check; still handle failures.

Validate paths from users, restrict access to an approved directory, and avoid logging secrets or sensitive data.

10. Why asynchronous programming?

Reading a large file or waiting for an HTTP response can take time. Synchronous code waits before moving to the next statement. Asynchronous I/O allows the caller to resume other work while an incomplete operation is pending.

Synchronous timeline

CallerStartBlocked waiting for I/OContinue

Asynchronous timeline

CallerStart I/OOther workResume
I/OStartOperation pendingDone
Async does not automatically mean a new thread, parallel execution or faster individual operations. It is especially useful for I/O-bound workloads and responsiveness.

11. Task, async and await syntax

Task represents an operation that may finish later. Task<T> represents an operation that returns a value. async permits await inside a method; await asynchronously waits for completion and retrieves the result.

static async Task DoWorkAsync()
{
    await Task.Delay(1000);
}
static async Task<int> GetNumberAsync()
{
    await Task.Delay(1000);
    return 42;
}
Call async method
→
Task returned when pending
→
await task
→
Resume with result

First async example

Observe the order of execution.

Console.WriteLine("Start");
Task job = WorkAsync();
Console.WriteLine("Other work");
await job;
Console.WriteLine("Finish");

static async Task WorkAsync()
{
    await Task.Delay(1000);
    Console.WriteLine("Work completed");
}

Expected output

Start
Other work
Work completed
Finish

The async method starts synchronously until it reaches an incomplete await. Task.Delay simulates waiting without blocking a thread. The caller resumes after awaiting the task.

12. Async file operations

Write and read a file asynchronously

Use async APIs for I/O rather than manually creating threads.

string path = "async-notes.txt";
await File.WriteAllTextAsync(path, "Async file handling");
string content = await File.ReadAllTextAsync(path);
Console.WriteLine(content);

Expected output

Async file handling

Await the write before reading, ensuring the write has completed. Exceptions are observed when awaiting the task.

Read a file incrementally

Use ReadLineAsync with a StreamReader.

await File.WriteAllLinesAsync("async-lines.txt", new[] { "One", "Two" });
using var reader = new StreamReader("async-lines.txt");
string? line;
while ((line = await reader.ReadLineAsync()) != null)
    Console.WriteLine(line);

Expected output

One
Two

StreamReader supports asynchronous reads. This avoids loading all lines at once. Its synchronous Dispose is sufficient here.

Asynchronous stream copy

Enable asynchronous file access and dispose streams.

await File.WriteAllTextAsync("input.txt", "File copy");
await using (var input = new FileStream("input.txt", FileMode.Open,
    FileAccess.Read, FileShare.Read, 4096, useAsync: true))
await using (var output = new FileStream("output.txt", FileMode.Create,
    FileAccess.Write, FileShare.None, 4096, useAsync: true))
{
    await input.CopyToAsync(output);
}
Console.WriteLine(await File.ReadAllTextAsync("output.txt"));

Expected output

File copy

await using calls DisposeAsync; the destination is closed before reading it.

13. Sequential vs concurrent tasks

Run independent operations concurrently

Start both tasks before waiting for them.

using System.Diagnostics;
var watch = Stopwatch.StartNew();
Task<string> first = GetAsync("Report A");
Task<string> second = GetAsync("Report B");
string[] results = await Task.WhenAll(first, second);
Console.WriteLine(string.Join(", ", results));
Console.WriteLine($"Elapsed: {watch.ElapsedMilliseconds} ms");

static async Task<string> GetAsync(string name)
{
    await Task.Delay(1000);
    return name;
}

Expected output

Report A, Report B
Elapsed: approximately 1000 ms

WhenAll waits for every task. Independent waits overlap. Awaiting each operation before starting the next would take approximately 2000 ms. Timings vary.

Start A + B
→
Both pending
→
WhenAll
→
Both complete
Do not concurrently write to the same file without coordination. Task.WhenAll is not a guarantee of CPU parallelism. Limit concurrency for large workloads.

14. Cancellation and exception handling

Cancel a pending task

Cancellation is cooperative: pass a token to methods that support it.

using var cts = new CancellationTokenSource();
cts.CancelAfter(500);
try
{
    await Task.Delay(3000, cts.Token);
    Console.WriteLine("Completed");
}
catch (OperationCanceledException)
{
    Console.WriteLine("Operation cancelled");
}

Expected output

Operation cancelled

The token signals cancellation. Await observes the cancellation exception. Real operations can finish before cancellation arrives.

Catch asynchronous file errors

Await inside try/catch.

try
{
    string data = await File.ReadAllTextAsync("missing-async-demo.txt");
    Console.WriteLine(data);
}
catch (IOException ex)
{
    Console.WriteLine($"Read failed: {ex.GetType().Name}");
}

Expected output

Read failed: FileNotFoundException (if absent)

Exceptions from faulted tasks surface at await. Do not discard tasks when you need to observe completion or errors.

15. CPU-bound vs I/O-bound work

WorkRecommended approach
File/network/database waitingUse native async APIs and await
Expensive CPU computation in a UI appConsider Task.Run to offload work
Independent operationsTask.WhenAll, with appropriate concurrency limits

Offload a CPU computation

Demonstrate Task.Run with a calculation.

long result = await Task.Run(() =>
{
    long sum = 0;
    for (int i = 1; i <= 1000000; i++) sum += i;
    return sum;
});
Console.WriteLine(result);

Expected output

500000500000

Task.Run schedules work on the thread pool. It does not reduce CPU cost and is not a replacement for asynchronous I/O. In ASP.NET Core, avoid unnecessary Task.Run for ordinary request processing.

Prefer await over .Result or .Wait(), which block threads and can cause deadlocks in some synchronization contexts. Use async void only for event handlers that require void.

16. Real-world project: employee report

A reporting application saves employee records as JSON, reloads them asynchronously, and produces a text summary. It demonstrates persistent storage, serialization, LINQ and async/await together.

Employee list
→
JSON file
→
Async read
→
Calculate summary
→
Report file

Complete employee report application

Replace Program.cs with this complete example.

using System.Text.Json;
string folder = Path.Combine(Environment.CurrentDirectory, "Reports");
Directory.CreateDirectory(folder);
string dataPath = Path.Combine(folder, "employees.json");
string reportPath = Path.Combine(folder, "summary.txt");
var employees = new List<Employee>
{
    new(1, "Anu", 45000), new(2, "Ravi", 55000), new(3, "Meera", 50000)
};
try
{
    await SaveAsync(dataPath, employees);
    var loaded = await LoadAsync(dataPath);
    string report = $"Employees: {loaded.Count}\n" +
                    $"Total salary: {loaded.Sum(e => e.Salary):F2}";
    await File.WriteAllTextAsync(reportPath, report);
    Console.WriteLine(await File.ReadAllTextAsync(reportPath));
}
catch (IOException ex)
{
    Console.WriteLine($"File error: {ex.Message}");
}
catch (JsonException ex)
{
    Console.WriteLine($"Invalid JSON: {ex.Message}");
}
static async Task SaveAsync(string path, List<Employee> employees)
{
    await using var stream = File.Create(path);
    await JsonSerializer.SerializeAsync(stream, employees,
        new JsonSerializerOptions { WriteIndented = true });
}
static async Task<List<Employee>> LoadAsync(string path)
{
    await using var stream = File.OpenRead(path);
    return await JsonSerializer.DeserializeAsync<List<Employee>>(stream)
           ?? new List<Employee>();
}
record Employee(int Id, string Name, decimal Salary);

Expected output

Employees: 3
Total salary: 150000.00 (culture dependent)

SaveAsync serializes directly into a stream; LoadAsync reads it back. Each operation is awaited in dependency order. The report is written only after the data has been loaded. For production, add access controls, cancellation, validation and atomic replacement where needed.

19. Interview questions and recap

What is File vs FileInfo?

File provides static convenience methods. FileInfo represents a file and exposes instance methods and metadata.

Why use using?

It ensures resources are disposed when leaving the scope, including when an exception occurs.

What is the difference between WriteAllText and AppendAllText?

WriteAllText replaces existing content; AppendAllText adds to it.

Why use serialization?

To persist or exchange structured objects in a defined format such as JSON.

What does async mean?

It enables await in a method; it does not automatically create a thread.

What does await do?

It observes completion and obtains the result or exception. While a task is incomplete, an async method can return control to its caller.

Task vs Task?

Task represents completion; Task also provides a result.

Task.Delay vs Thread.Sleep?

Task.Delay returns a task without blocking a thread for the delay. Thread.Sleep blocks the calling thread.

When should Task.WhenAll be used?

When multiple independent tasks have been started and all results or completions are needed.

What is cancellation?

A cooperative request to stop; the operation must observe the token.

How do you handle async exceptions?

Await the task inside a try/catch block.

Why avoid async void?

The caller cannot await it or observe its completion through a Task; reserve it for appropriate event handlers.
