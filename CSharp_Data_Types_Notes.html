Data Types and Core Concepts in C#

1. Value Types and Reference Types

In C#, data types are categorized into two main groups based on how they store their values in memory: Value Types and Reference Types.

  • Value Types: Store the data directly. They are allocated on the Stack. When you assign one value type to another, a direct copy of the value is made. Examples: int, float, double, bool, struct, enum.
  • Reference Types: Store a reference (memory address) to the actual data. The actual data is stored on the Heap. When you assign one reference type to another, both point to the same memory location. Examples: string, class, array, delegate.
// Value Type Example
int a = 10;
int b = a; // b is a copy of a (b = 10)
b = 20; // changing b does not affect a (a is still 10)

// Reference Type Example
int[] arr1 = new int[] { 1, 2, 3 };
int[] arr2 = arr1; // arr2 points to the same array in memory
arr2[0] = 99; // changing arr2 ALSO changes arr1 (arr1[0] is now 99)

2. Boxing and UnBoxing

Boxing is the process of converting a Value Type to a Reference Type (specifically, to the object type). It is an implicit conversion.

Unboxing is the reverse process: converting a Reference Type (an object) back to a Value Type. It requires an explicit cast.

Performance Impact: Boxing and unboxing are computationally expensive because they involve memory allocation on the heap and type checking. Avoid them in performance-critical loops.
int num = 123;
object obj = num;     // Boxing (Value type -> Reference type)
int num2 = (int)obj;  // Unboxing (Reference type -> Value type)

3. Arrays (Single, Multi-Dimensional & Jagged)

  • Single Dimensional Array: A linear sequence of elements of the same type.
  • Multi-Dimensional Array: A rectangular array with multiple dimensions (e.g., a matrix or grid). Represented by commas inside brackets [,].
  • Jagged Array: An "array of arrays" where each inner array can have a different length. Represented by multiple brackets [][].
// Single Dimensional
int[] numbers = { 1, 2, 3, 4, 5 };

// Multi-Dimensional (2D Matrix: 2 rows, 3 columns)
int[,] matrix = new int[2, 3] {
    { 1, 2, 3 },
    { 4, 5, 6 }
};

// Jagged Array (Array of arrays)
int[][] jaggedArray = new int[3][];
jaggedArray[0] = new int[] { 1, 2 };
jaggedArray[1] = new int[] { 3, 4, 5 };
jaggedArray[2] = new int[] { 6 };

4. Nullable Types

By default, value types cannot be assigned a null value. To allow a value type to store null, C# provides Nullable Types using the ? modifier.

int? nullableInt = null; // Valid
bool? isTrue = null;

if (nullableInt.HasValue) {
    Console.WriteLine(nullableInt.Value);
} else {
    Console.WriteLine("Value is null");
}

// Null-coalescing operator (??)
int result = nullableInt ?? 0; // If nullableInt is null, return 0

5. Implicitly Typed Local Variables (var)

The var keyword allows the compiler to infer the type of a local variable from the expression on the right side of the initialization statement. It is strongly typed; the type is locked at compile-time.

var name = "John"; // Compiler infers 'string'
var age = 30;      // Compiler infers 'int'
var list = new List<string>(); // Compiler infers 'List<string>'

// age = "Thirty"; // ERROR: age is strictly an int, cannot assign a string

7. 'is' and 'as' Operators

Used for safe type checking and casting without throwing exceptions.

  • is: Checks if an object is compatible with a given type. Returns true or false.
  • as: Attempts to cast an object to a specific type. Returns the casted object if successful, or null if it fails.
object obj = "Hello World";

// 'is' operator
if (obj is string str) {
    Console.WriteLine($"It's a string with length {str.Length}"); // Pattern matching
}

// 'as' operator
string myStr = obj as string;
if (myStr != null) {
    Console.WriteLine("Cast successful");
}

8. Ref vs Out Keywords

Both are used to pass arguments by reference (so changes inside the method affect the original variable), but they have different initialization rules.

  • ref: The variable must be initialized before it is passed to the method. The method is not forced to modify it.
  • out: The variable does not need to be initialized before passing. However, the method must assign a value to it before returning.
void ModifyRef(ref int x) {
    x += 10;
}

void GetMultipleValues(out int a, out string b) {
    a = 100; // MUST assign a value
    b = "Done"; // MUST assign a value
}

int refValue = 5; // Must initialize
ModifyRef(ref refValue);

int outInt; // Initialization not required
string outString;
GetMultipleValues(out outInt, out outString);

9. The 'object' base class in .NET

The System.Object (or object in C#) is the ultimate base class for all data types in the .NET Framework. Every type (value type or reference type) implicitly inherits from it.

It provides basic methods like ToString(), Equals(), GetHashCode(), and GetType().

10. Equals() vs ==

  • == (Operator): By default, compares object references for reference types, and values for value types. Note: For the string class, == is overloaded to compare the actual string values, not the references.
  • Equals() (Method): A virtual method from the object class. By default, it works like == (reference equality), but it is heavily overridden in many classes (like string, custom classes) to check for value equality.
string s1 = new string(new char[] { 'h', 'i' });
string s2 = new string(new char[] { 'h', 'i' });

Console.WriteLine(s1 == s2);      // True (overloaded for value comparison in strings)
Console.WriteLine(s1.Equals(s2)); // True

object o1 = s1;
object o2 = s2;
Console.WriteLine(o1 == o2);      // False (comparing memory addresses/references)
Console.WriteLine(o1.Equals(o2)); // True (polymorphism calls overridden string.Equals)

11. String vs StringBuilder

  • String: Immutable. Once a string object is created, its value cannot be changed. Any operation that appears to modify a string actually creates a brand new string object in memory. Poor performance for heavy string manipulation in loops.
  • StringBuilder: Mutable. Located in System.Text. It modifies the existing string buffer without creating new objects. Excellent performance for heavy string concatenations.
// Bad practice in loops (creates 1000 string objects)
string s = "";
for (int i = 0; i < 1000; i++) {
    s += i.ToString(); 
}

// Good practice (uses the same memory buffer)
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) {
    sb.Append(i.ToString());
}
string final = sb.ToString();

12. Various String Class Methods

Commonly used methods in the string class:

  • Substring(int startIndex, int length): Extracts a portion of the string.
  • Replace(oldChar, newChar): Replaces occurrences of a character/string.
  • Split(char separator): Splits a string into an array of strings based on a delimiter.
  • Trim(): Removes leading and trailing whitespaces.
  • ToUpper() / ToLower(): Converts casing.
  • Contains(string substring): Returns true if the substring exists within the string.
  • StartsWith() / EndsWith(): Checks prefixes and suffixes.
  • string.IsNullOrEmpty(str): Checks if a string is null or empty.
string text = " Hello World ";
string trimmed = text.Trim(); // "Hello World"
string upper = trimmed.ToUpper(); // "HELLO WORLD"
string[] words = trimmed.Split(' '); // ["Hello", "World"]
string sub = trimmed.Substring(0, 5); // "Hello"
bool hasWorld = trimmed.Contains("World"); // True

13. Default Parameters, Named Parameters

Introduced in C# 4.0 to make method calls more flexible.

  • Default Parameters: Allow you to assign default values to method parameters. If the caller doesn't provide a value, the default is used.
  • Named Parameters: Allow you to pass arguments to a method by matching the argument with its parameter name, rather than its position.
// 'greeting' has a default parameter
void PrintMessage(string name, string greeting = "Hello") {
    Console.WriteLine($"{greeting}, {name}!");
}

PrintMessage("Alice"); // Output: Hello, Alice!
PrintMessage("Bob", "Hi"); // Output: Hi, Bob!

// Named parameters (order doesn't matter)
PrintMessage(greeting: "Welcome", name: "Charlie");

14. Parse() vs TryParse() vs Convert Class

All are used for type conversion (e.g., string to int), but handle failures differently:

  • Parse(): Converts a string to a specific type. Throws an exception (e.g., FormatException, ArgumentNullException) if the conversion fails.
  • TryParse(): Safely attempts conversion. Does not throw exceptions. Returns true if successful and places the result in an out parameter. Returns false if it fails.
  • Convert.ToInt32() (etc.): A static class method. It handles null strings gracefully (returns 0 instead of throwing ArgumentNullException). However, it still throws a FormatException for invalid formats.
string validNumber = "123";
string invalidNumber = "ABC";
string nullString = null;

// Parse (Throws exception if invalid or null)
int num1 = int.Parse(validNumber); // Works
// int error1 = int.Parse(invalidNumber); // Throws FormatException
// int error2 = int.Parse(nullString); // Throws ArgumentNullException

// TryParse (Safe, doesn't throw)
if (int.TryParse(invalidNumber, out int result)) {
    Console.WriteLine($"Success: {result}");
} else {
    Console.WriteLine("Conversion failed safely.");
}

// Convert (Handles null gracefully)
int num3 = Convert.ToInt32(nullString); // Returns 0 safely
// int error3 = Convert.ToInt32(invalidNumber); // Throws FormatException
